# DEV_LOG — Sport Buddy

## Помилки (точний текст → причина → виправлення)

### 1. Попередження ESLint `react-refresh/only-export-components`
- **Текст:** `src/components/ui/TextField.tsx 3:14 warning Fast refresh only works when a file only exports components. Use a new file to share constants or functions between components` (і 2 такі ж у `src/hooks/useAuth.tsx`).
- **Причина:** `TextField.tsx` експортував функцію `fieldClass` поряд із компонентами; `useAuth.tsx` експортує провайдер і хуки з одного файлу.
- **Виправлення:** `fieldClass` винесено в `src/components/ui/fieldClass.ts`; для `src/hooks/**/*.tsx` правило вимкнено в `eslint.config.js` (провайдер + хук в одному файлі — свідоме рішення).

### 2. Екран «Supabase не налаштовано», хоча `.env.local` існує
- **Текст:** на сторінці `Supabase не налаштовано. Створіть файл .env.local…`.
- **Причина:** панель Supabase (Connect → React/Vite) пропонує змінну `VITE_SUPABASE_PUBLISHABLE_KEY`, а код читав лише `VITE_SUPABASE_ANON_KEY` → `isConfigured = false`.
- **Виправлення:** `src/api/supabase.ts` приймає обидві назви; `.env.example` доповнено.

### 3. Попередження Vite про розмір чанка
- **Текст:** `(!) Some chunks are larger than 500 kB after minification.` (`index-*.js 533.88 kB`).
- **Причина:** після додавання Leaflet усі бібліотеки потрапили в один чанк.
- **Виправлення:** `build.rollupOptions.output.manualChunks` у `vite.config.ts` (react / supabase / map). Найбільший чанк тепер 165 kB.

### 4. Realtime губить першу подію після підписки
- **Текст (scripts/realtime-test.mjs, перший запуск):**
  ```
  ❌ глядач отримав подію про новий запис — confirmed_count=null
  ❌ затримка ≤ 2 с — null мс
  ✅ скасування доходить ≤ 2 с, вільне місце повернулось — 1080 мс
  ✅ учасник отримав повідомлення чату в реальному часі — 12154 мс
  ```
- **Причина (перевірено діагностичним скриптом, а не припущенням):** статус `SUBSCRIBED` означає лише приєднання до каналу. Фільтр `postgres_changes` (з перевіркою RLS) стає активним пізніше — коли сервер надсилає `system: {"message":"Subscribed to PostgreSQL","status":"ok","extension":"postgres_changes"}` (у замірі: SUBSCRIBED на 1364 мс, готовність на 1637 мс). Події між цими моментами втрачаються. У застосунку це означало: запис іншого користувача в першу ~секунду після відкриття картки не з'являвся без перезавантаження.
- **Виправлення:** `src/hooks/useRealtime.ts` вважає канал готовим лише після system-події `postgres_changes: ok` і в цей момент один раз перечитує дані (закриває проміжок між першим завантаженням і підпискою); тест чекає ту саму подію.
- **Після виправлення:** затримка 235 мс / 521 мс / 599 мс — усі 5 перевірок ✅.

### 5. (не помилка коду) `npm run test:db | Select-String "✅|❌"` нічого не вивів
- **Причина:** PowerShell 5.1 у конвеєрі декодує UTF-8-вивід Node не в тій кодуванні, тож емодзі не збігаються з шаблоном. Сирий вивід — усі перевірки ✅. Висновок: перевіряти вивід скриптів без фільтра `Select-String`.

### Ітерація 7 — рівень користувача
**Зроблено:**
- **Пошук:** якщо в URL немає жодного фільтра (`sport`, `level`, `lat`/`lng`), початковий фільтр рівня береться з профілю (`resolveFilters` у `src/lib/filters.ts`). Якщо в URL є фільтри, вони мають пріоритет. `serializeFilters` тепер завжди пише `level` (значення `all`, якщо рівень не обрано). Тому після зняття чипа або «Скинути фільтри» рівень з профілю не підставляється знову.
- **Заявки (US 1.2):** перевірено, що аватар, ім'я та рівень кандидата вже показувались (`OrganizerTrainingBlock`, рядок «<Рівень> · <рейтинг>»). Змін не потрібно.
- **Запис:** `levelWarning` у `src/lib/bookingState.ts`. Якщо рівень тренування вищий за рівень користувача, перед записом з'являється блок підтвердження «Це тренування рівня «просунутий», твій рівень — «новачок». Все одно записатися?» з кнопками «Так, записатися» / «Ні». Запис не блокується, перевірки в БД не змінювались.
- **Профіль:** новий екран `/profile`, відкривається з аватарки в шапці. На ньому можна змінити рівень. Оновлення йде напряму в `profiles`: RLS `profiles_update_own` і `grant update (level)` уже були в 0001, тому міграція не потрібна. Після збереження `refreshProfile()` у `AuthContext` одразу оновлює рівень у пошуку й у попередженні.

**Тести:** `resolveFilters` (початковий рівень з профілю; URL має пріоритет; скинуті фільтри не повертають рівень; без профілю), `levelWarning` (лише для вищого рівня; точний текст). e2e пошуку доповнено: у olga@ «Середній» вибрано автоматично.

**Перевірено:** build ✅, lint ✅, `npm test` ✅ 63, `npx playwright test e2e/search-and-card.spec.ts` ✅ 2.

2. Натиснути «Новачок» (зняти вибір) і оновити сторінку: рівень знову не підставився, в URL `level=all`.

5. На тренуванні рівня «новачок» попередження немає.
